# Action-Preconditioned Evidence Preservation for Packing and Handover

The primary research direction is **content provenance and delayed verification before packing, repacking and handover change evidence availability or item-container binding**. Codex handles reasoning, bounded tools, versioned evidence and offline regression; frozen benchmark-specific π0.5 policies handle motor execution.

The new task set contains 144 development, 240 validation, 480 test and 720 reserve conditions in 396 constructor clusters. Four dependent condition siblings share a cluster; formal test has 120 clusters. Nine workflows are seen during development, three complete workflows are held out; half the test conditions use new workflow-carrier compositions. Component training is optional and reserved within development, with no training performed.

The dedicated [physical scene package](research/packing_physics_20261111/README.md) now adds actual native initialization, camera/mark-availability, dynamic-workflow and custom-scoring checks, plus frozen-policy interface prefixes. Exact counts and limits are in its construction receipt. These are zero-GPT engineering checks: privileged fixture success is not robot or method success, and complete paid Codex episodes have not been validated. The fixed method matrix remains disabled. The physical revision removes wait-only workflow duplicates; historical protocol definitions are preserved.

Candidates are P1 pre-commit inspection, P2 budgeted source coverage and P3 binding revision. Strong controls share the original-image archive, ordinary execution modules, model, frozen policy/norm, 64k configuration, action interface and scoring budgets. Only evidence-related context modules vary. The common framework is infrastructure, not a claimed method contribution.

Answer-bearing constructor data, heldout identities, RGB, HTTP, credentials and weights stay off this public index. The full private task package and protocol traces are on the authorized server data volume. Historical results and locked sources are preserved; old held queues are not resumed.
