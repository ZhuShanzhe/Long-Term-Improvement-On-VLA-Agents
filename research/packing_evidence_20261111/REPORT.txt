# 装箱与交接流程中的行动前证据保全
## 内容溯源、对象绑定与延迟复核
研究开题报告 · 研究方案与技术路线
2026年11月11日 · 修订稿

# 一 研究定位与方法边界
## 1. 拟解决的问题
机器人在装箱、换装和交接时，既改变物体位置，也改变之后能够取得的证据。装入不透明容器前没有看见的标记，不能由检索补回；已经观察的内容可以从原图回取；发生换装后，旧记录仍然真实，但不能直接证明物体现在属于哪个容器。

本研究聚焦：在这些操作发生之前，如何判断延迟复核所需的证据是否仍可获得，并以较小代价维持内容与容器之间的可靠联系？研究对象是取证时机及证据使用条件，而非通用长程任务刷分或工业缺陷检测。

场景限制在干燥物品、较大的可辨识标记、少量容器及常规抓放。批次符号采用单字符；不把微小文字识别、精细测量、液体倾倒或复杂开门作为主任务难点。

[[evidence_states]]

## 2. 研究范围
只研究公开信息能够支持的判断。未来问题的候选类型提前公布，具体问题稍后按预定规则到达；不向策略泄露实际分支。所有组保留同样的原图档案和历史回取工具。

主要载体采用已适配的冻结LIBERO π0.5路线。已有benchmark用于复用环境、资产和执行接口；新任务使用独立版本的自建评分，不冒称官方RoboMemArena或LIBERO成绩。

# 一 研究定位与方法边界（续）
## 3. 拟议贡献与可检验假设
**行动前获取判断。** 对候选装箱、封装、换装或交接操作，分别判断历史是否可回取、是否需要重新观察、当前绑定是否待核实，允许多条途径同时成立，并保留unknown。

**预算内的证据交付。** 由未来复核需要决定最小证据集合。在活动空间有限时，先覆盖必要来源，再补细节；检查实际请求收到的卡片，而非仅统计档案是否保存成功。

**交接中的绑定有效性。** 将不可变观察史与可修订的当前归属分开。公开结果不足时，旧归属进入待核实状态，不以动作指令或工具成功回包代替物理确认。

H1：相同原图、查询和执行预算下，行动前判断减少封装后无法补回的取证缺口。

H2：硬性来源覆盖比只按近期性或相关性排序，更稳定地支持多来源延迟复核。

H3：显式处理绑定待核实，减少换装后错误接受旧记录；收益不能只来自更多拒绝。

H4：低风险、可重查和与证据无关的对照中，额外取证与阻塞应保持较低。

## 4. 创新边界
主动感知、外部记忆、事件账本、前置条件检查和短skill均已有工作。垂类名称本身不构成创新。拟检验的差异是：**操作改变证据可得性时，行动前选择是否在固定预算下改善后续内容溯源与交接判断。**

与前瞻记忆相比，强调物理获取窗口与当前归属；与事后修订相比，比较变化发生前的选择；与工业计量检查相比，不测量几何公差，不凭完整性规则单独宣称新意。若提升仅来自公共执行修复、较大上下文或额外观察，应相应收缩贡献。

# 二 任务集与评测协议
## 1. 三类核心任务
| 任务族 | 典型流程 | 关键检验 |
| 装箱前取证 | 查看底部标记后装箱；先看后遮挡；双来源配套；嵌套装箱 | 从未取得的信息与可回取历史能否区分 |
| 内容与容器绑定 | 直接分装；单件换装；交换容器内容；拆分后合并 | 旧来源能否支持当前归属 |
| 延迟工单复核 | 后到工单；交接后退回再装；两单排队；合并后的延迟问题 | 在具体问题未知时保留必要来源，之后选对分支 |

共12种流程图。三种候选物理载体为分隔托盘、不透明纸箱和交接周转箱。载体差异必须体现为观察条件、可用操作和重查代价，不能只改名称。不同载体的新物理场景须分别通过资格检查。

## 2. 配对条件
每个场景构造簇生成四条条件：需要历史证据且不可重查、需要历史证据且允许重查、不依赖该历史证据且不可重查、不依赖该历史证据且允许重查。配对保留物品、初态和普通工作负担，仅改变预先公布的复核需求或合法恢复条件。

“不可重查”指公开流程不允许在交接后重新取出，而非人为删除已经取得的图像。工作流内正常退回、开包和换装不等于允许任意事后重查。未观察的信息不能由构造器自动写进档案。

## 3. 避免能力混杂
先使用已能完成的抓放母任务，逐步增加可辨识标记、容器遮挡和归属变化。各阶段先检查公共执行、原图回取及自建评分，再比较证据方法。必要的相机、状态和错误边界修复对所有组一致，不计为研究收益。

# 二 任务集与评测协议（续）
## 4. 规模与划分
沿用原规划最近版本的规模与分层方式，主任务重建，不将旧通用任务直接改名计入新主面板。

| 划分 | 条件数 | 构造簇数 | 用途 |
| 开发 | 144 | 36 | 72条组件训练预留，72条开发调试；当前先不训练 |
| 验证 | 240 | 60 | 按固定协议选择方法和冻结参数 |
| 正式测试 | 480 | 120 | 240条未见流程；240条未见流程与载体组合 |
| 扩展预留 | 720 | 180 | 正式测试前依功效分析决定是否启用 |
| 总计 | 1584 | 396 | 每簇四条相关条件，不是1584个独立场景 |

三个任务族在各划分内均衡。开发、验证共享九种流程但不共享场景簇；三个完整流程留作未见流程测试。另一半正式测试使用开发流程与未见载体的组合。单纯换seed或颜色不称未见任务。

同一场景的四个条件及其相邻视频、缓存、派生记录、反事实前缀必须留在同一划分。训练与调试簇分离；不得用验证或测试答案修改skill、选择器或阈值。机器进行全量协议检查不等于将留出答案送给模型。

## 5. 开发面板
单数据面板保留一个簇的四个条件，先比较强基座与一条候选路线。快速面板选8条开发条件覆盖三个任务族；12条断点面板为三个完整配对簇。面板在模型运行前固定，不按候选方法成功情况筛例。

已有RoboMME任务仅作记忆机制控制，LADDER、LIBERO-PRO和RoboCasa作为少量独立迁移复核；不再把旧310条通用原生任务默认加入主贡献的分母。迁移测试单独列出模型、权重、动作及原评分配置。

# 二 任务集与评测协议（续）
## 6. 主要指标与诊断
| 层次 | 指标 | 解释边界 |
| 主要效果 | 有来源支持的延迟复核正确率；错误接受率与接受覆盖率 | 同时报告unknown，不能靠全部拒绝取胜 |
| 获取 | 获取窗口关闭前取得必要证据的比例 | 看到ID或图像文件存在不等于取得语义 |
| 保存与选择 | 首次需要时实际请求的必要来源覆盖率 | 入库、选中、渲染、交付、使用分别记录 |
| 绑定 | 换装后当前归属正确率；旧绑定误用率 | 工具ACK、动作提案或机器人运动均不能独立证明归属 |
| 完整任务 | 自建原生终局的有效True、False和UNKNOWN | 断点停止、接口异常和缺结果不记任务False |
| 成本与无害性 | 取证、重查、返工、控制步、宿主调用及低风险额外干预 | 在相同效果下比较成本，不预设一定省token |

token按每例最后累计usage统计，并分列缓存输入与输出；不逐轮叠加累计值，不把中转服务usage直接当账单。卡片字节缩短不必然导致模型输入或付费同比下降。

## 7. 统计与因果控制
以场景簇为统计单元，报告配对差值和95%区间；条件和事件嵌套在簇内。正式主要对比为最终候选对事后检索账本、最终候选对全部先检查；两项主对比采用Holm校正，其他消融作为探索分析。

120个测试簇沿用原规模，不是显著性保证。开发期估计配对不一致率和簇内相关性，在读取正式测试结果之前冻结120簇或含预留的300簇方案。报告全部任务结果及取得证据后的条件指标，不能仅展示后者。

自然64k压缩、共同手动压缩和协议工作状态清空分开报告。不能把合成回放当自然压缩收益，也不能把一次正确回答当物理执行成功。

# 三 相关工作与可迁移思路
## 1. 相近工作与本课题侧重
| 工作 | 可借鉴部分 | 需要区分的贡献 |
| Chameleon、TRACE | 历史线索支持延迟动作、控制相关记忆 | 不能将前瞻记忆或延迟线索首次提出作为贡献 |
| REMM | 不可变证据史、可修订状态、依赖撤回 | 用作强事后修订对照；检验行动前增加的价值 |
| FRAME | 可追溯证据、覆盖检查、未知不授权PASS | 本研究不做校准计量；完整性门控本身不是新方法 |
| ReadAgent、MemGPT | 短摘要与原文回取、分层存储 | 借用公共档案机制，不把外部存储包装成创新 |
| xQuAD、多样化检索 | 不同潜在需求的覆盖 | 任务来源覆盖还需固定预算、真实交付和物理窗口 |
| SAM2Act+ / MemoryBench | 将记忆相关难点独立成任务并设置泛化 | 原训练策略不能直接当冻结π0.5的同配置比较 |

近期预印本与正式发表论文分开标注。上述工作与本研究部分问题直接相近，区别需由受控实验支持，而不是宣称“无人做过”。

## 2. Coding agent的独特作用
借鉴HexaShell的通用执行代码加简短任务skill组织方式：公共代码管理环境、工具、档案、引用和预算；短skill表达装箱前检查、绑定待核实和延迟复核规则。保留冻结π0.5执行，不引入其新的感知、几何抓取或运动控制模块。[3]

Codex的优势是能够查询和维护版本化证据文件、运行受限程序、把错误轨迹变成可复查回归用例。在线仅使用冻结白名单工具；离线可生成规则测试和候选代码，不能在正式测试中访问隐藏评分、未来帧或在线改程序。

# 四 Codex实现蓝图与实验路线
## 1. 公共架构
[[architecture]]

公共层保存原始观察及来源、普通工具回包、预算和档案版本；研究层仅改变证据判断、选择和呈现。公开传感器返回的结构化字段不等于真实RGB自动具备的能力：原型协议可用明确字段检验逻辑，物理实验仍须由原图支持可错的视觉判断。

普通任务规划、稳定的任务级指令、相机与本体适配、原图回取、工具错误恢复和终止分类对各组相同。每条benchmark仍使用自己的冻结启动器，不混用动作语义或归一化。

## 2. 路线P1：行动前检查
在装箱、合装、封装、换装和交接提案前，生成有界检查记录：可能的后续问题、已有支持、候选操作及其公开效果、允许的恢复手段和待办证据。

若未取得必要字段且操作后无法合法取得，先通过原工具观察；若历史已足够，则按需检索；不确定时保留待核实。初期采用小型领域契约和短skill，不从完整世界模型或额外模型代理起步。检查器输出建议，由宿主按原动作接口执行，不能绕过工具预算。

# 四 Codex实现蓝图与实验路线（续）
## 3. 路线P2：多来源最小覆盖
在P1基础上，将短语义卡与完整来源链分开。先为每个必要对象与字段保留最小条目，再填充附加细节。底层引用仍逐一计入八引用上限，索引指针不能绕过额度。

容量不足时显式输出coverage_shortfall，不整条静默跳过关键来源，不以“保存过”代替“当前请求拿到”。每次记录turn、request、卡片版本、字节数及实际覆盖项。交付证明仅说明字节进入该请求，不说明模型已理解或物理事实无误。

## 4. 路线P3：交接绑定与待核实
在P2基础上，维护观察事件、内容断言和当前归属的版本。物体换装时，确认的公开结果支持新绑定；部分遮挡、操作中断或证据不足时标记待核实，并在延迟复核前请求有界重查。

历史事实不删除，旧绑定也不能继续冒充当前归属。对比P2与P3时只改变归属修订及其上下文提示；额外观察同样扣预算。该路线借鉴REMM式状态修订，但主要检验交接前的预防与后续绑定核查是否互补。[1]

## 5. 对照与消融
六个候选比较组为：公共原图档案、全部先检查、事后检索账本、P1、P2、P3。开发先比较事后账本与P1，再依据固定验证规则推进P2/P3，不预设三条路线都必须成为最终方法。

正式实验至少保留事后账本、全部先检查及已冻结的最终候选。消融分别移除行动条件、硬覆盖或绑定修订；活动空间、引用、读写和动作预算不变。若短skill或简单规则已经同样有效，应据实报告，不为复杂性追加训练。

# 四 Codex实现蓝图与实验路线（续）
## 6. 分阶段实施与断点
**阶段0：全量离线协议。** 检查任务可达性、四条件配对、未观察信息不可从档案恢复、可重查分支可达、公共输入隔离、来源与字节预算、跨划分泄漏。模拟操作只证明协议闭环，不证明RGB、π执行或方法效果。

**阶段1：公共物理载体。** 从已验证抓放母任务引入一种载体，检查重置与渲染、标记可辨性、操作后的可获取性、历史原图回取、物理绑定、统一评分和完整预算。每项可复查后才启用该载体的方法测试；不能靠修改姿态或私有目标直接完成操作。

**阶段2：少量开发断点。** 先用一个配对簇、两组；随后用8条快速面板和12条断点面板。在第8、24、64个宿主决策检查取证、来源交付、归属和接口。缺共同载体能力则修复公共层后另建版本，不把公共修复计作候选收益。

开发阶段可按预先公布的工程门槛停止无信息量前缀，结果为UNKNOWN。只有实际流程改善且公共执行可继续，才安排完整开发验证；该选择性延长不能用于估计正式任务胜率。

**阶段3：冻结验证与正式测试。** 在验证集依既定规则选择路线，冻结代码、skill、面板、终止协议和比较组。所有正式组采用相同原生终止和错误规则，不因某组早期表现更好才让其跑完。

## 7. 固定控制
统一gpt-6-astra/high、Codex0.149.1、64k公共配置、冻结LIBERO π0.5权重与norm、原RGB/本体、5×7 OSC/20Hz、2500原控制步和600宿主决策；原生有效False不追分重试。

沿用七槽规则，每逻辑请求每槽至多一次、每钥最多600秒，接口失败补齐未试候选；不设整例墙钟上限，不绕过原生成与工具预算。保留真实槽位、协议与时间记录；不将不同provider/profile混为受控胜率。训练仅限预留训练簇且不更新冻结上层模型或π权重；新增小组件须单独消融。
