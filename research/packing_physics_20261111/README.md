# PACK-EVID 物理任务集

研究范围是装箱、换装与交接中的行动前证据保全。新场景使用原生 MuJoCo 接触、自由刚体、真实滑盖和带标记的 HOPE 包装物。标记随物体运动；遮挡来自几何体，没有视野掩码、动作后位姿赋值或向模型提供隐藏属性。

## 规模和划分

| 用途 | 条件数 | 构造簇数 |
|---|---:|---:|
| 开发 | 144 | 36 |
| 验证 | 240 | 60 |
| 测试 | 480 | 120 |
| 保留 | 720 | 180 |
| 合计 | 1584 | 396 |

开发中的72条预留给组件训练、72条用于调试；本次没有训练。每簇包含“需要/不需要内部证据 × 允许/禁止额外重开”四个配对条件，始终处在同一划分。四个条件不是四个独立任务。快速面板为4、8、12条，均来自开发集；不能用测试集反复调参。

## 多样性和泛化

实际包含12种工作流、33种工作流与载体组合、3种机械载体：分隔托盘、不透明纸箱、交接周转箱。物体为奶酪、黄油和饼干包装。变化覆盖主动翻面取证、初始可见后封盖、多来源配套、重新分装、交换、合并、交接后返回，以及晚到工作单。

旧定义去掉等待和角色名字后只有10种流程。本版用实际中转、分批装箱和返回重装替代等待位置差异；去掉纯等待、重命名物体和容器，并交换相互独立动作后，仍有12种不同依赖图。测试集中240条来自开发未见的3种完整流程，另外240条来自未见的流程与载体组合。所有构造簇按组划分，避免四个配对条件泄漏。

这是流程和组合泛化，不能据此声称未见物体、开放场景或真实机器人泛化。396个初始化也不等于396种场景设计。共用桌面、机器人和包装资产会产生视觉相似；精确画面重复、近似画面重复和完整任务重复分别审计，结果见 `PHYSICAL_DIVERSITY_AUDIT.json`。

实际审计得到：不同簇的完全相同RGB为0对，近似初始画面为13对（512位双相机灰度dHash距离≤6），其中9对跨划分。排除未用物体属性和随机种子后，近似画面且信息任务相同的跨划分重复为0。灰度哈希不能证明颜色或语义相同，因此没有直接把13对画面删除。

忽略布局后有58对相同信息任务的重复实例：开发—验证5对、测试—预留25对，其余28对在各自划分内部。开发—正式测试、验证—正式测试均为0。它们作为不同布局下的重复测量保留，不新增工作流计数；完整口径见 `TASK_SIMILARITY_AUDIT.json` 和 `INFORMATION_REPLICA_SPLIT_AUDIT.json`。

## 任务和评价

模型先执行普通装箱工作，再响应晚到的公开工作单。问题可能要求某件物体的标记/批次与当前容器，也可能要求指定容器内所有包装的属性列表。后者保留重复值，避免只按预定目的地回答的捷径。控制条件只询问外部交接标签，但仍须完成相同普通工作。

颜色、批次均只通过原始RGB可得。批次采用字母和大面积背景色的冗余编码，所有方法共享公开对照表，减少256像素下细小OCR造成的混淆。模型只能接收双相机RGB、本体状态、普通任务文字和观测引用；不接收位置真值、内部工作阶段、隐藏属性或评分。

共同工具边界为 `act`、`view`、`submit_verification`，档案读写和原图回取沿用原有公共额度。`submit_verification` 是任务规定的一次答复，不是隐藏评分查询；它不返回正确答案。非法参数返回可恢复的工具错误并计入预算，物理动作禁止重放。

所有方法共享原模型、高推理档、Codex0.149.1、64k、冻结LIBERO π0.5与归一化、原相机、本体、5×7 OSC20Hz、2500控制步和600宿主决策。每个密钥每逻辑请求最多600秒，失败自动尝试剩余指定槽位，整例无墙钟限制。仅 `evidence_module` 可变；公共修复必须整组采用同一版本。

原生完整任务结果要求自建评分器的严格有效布尔结果。断点和接口前缀为UNKNOWN，不能写成任务False。报告完整任务结果的同时，分别记录取证、写入、原图支持、后续交付、正确容器绑定和失效绑定；条件指标不能替代完整成功率。

## 代码与使用

- `geometry.py`、`pack_env.py`：物理资产、重置、原动作接口和私有任务评分。
- `task_port.py`：所有方法共用的受限工具边界；没有评分或真值读取工具。
- `run_case.py`：专用零上层API入口，最多3个冻结π动作块，用于检查接线；不会隐式启动付费整例。
- `release-physical/private/`：服务器侧构造参数与初始状态；不能暴露给模型或公开仓库。
- `release-physical/policy-inputs/`：实际公开任务文本。
- `effective-configs/`：六组公共配置及一致性收据；方法研究入口保持禁执行，防止把配置准备当成实验授权。
- `jig.py`：只供离线引擎验收的特权力/力矩夹具，严禁接入agent工具。它的正向评分仅验证几何与评分闭环，不是π0.5或方法成功率。

服务器原生Python与下载、缓存、状态和图片均位于数据盘。固定π入口通过既有相机/状态转换适配器复用原权重；不重新下载或安装。

```text
<native-python> run_case.py --case <开发面板ID> --run-name <全新目录名> --diagnostic-chunks 3
```

本入口只做接口前缀。真实Codex驱动及证据方法必须经共同宿主接入同一 `PackToolPort`；不得让研究方法调用特权夹具、读取私有构造文件，或因某组表现决定是否延长正式测试。完整付费整例的机器人可操作性与方法收益应另行报告。

## 验收范围

实际完成：3个载体的重置与原动作步进、66/66条工作流/重开规则组合、9/9项物体与载体的可见线索检查、1584/1584条实际初始化和动作接口、396/396簇初始与步进后配对一致性、3个载体各3次原冻结π推理，以及32项工具/评分/数据契约CPU检查。56个记录进程身份、所属进程组、GPU和全局锁均已结算。准确数量和源码锁见 `FINAL_PHYSICAL_RELEASE_RECEIPT.json`。

验收不调用GPT，不读取密钥。RGB差分只能证明图像有可区分信号，不能证明模型读懂；特权夹具只能证明引擎路径与评分可闭环，不能证明冻结π能完成新容器操作。本次不自动恢复旧28项、不启动新付费矩阵，也不覆盖历史实验。
